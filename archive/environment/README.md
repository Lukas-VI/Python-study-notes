# Environment Notes

这次整理没有移动当前的虚拟环境，而是把环境信息写在这里，方便以后回看。

## 当前观察到的环境

- 虚拟环境位置：`D:\py\.venv`
- `pyvenv.cfg` 记录的基础解释器：`C:\Python313\python.exe`
- 虚拟环境 Python 版本：`3.13.7`

## `requirements.txt` 的性质

根目录的 `requirements.txt` 有 443 行，明显更像一次完整环境导出，而不是某个单独项目的最小依赖列表。

这意味着：

- 它很适合当作“当时这台机器 / 这个环境大概装了什么”的快照。
- 它不一定适合直接当作所有脚本的精简依赖说明。
- 如果以后真的要恢复某一个旧脚本，更推荐单独建一个新环境，再按实际需要安装依赖。

## 为什么没有把 `.venv/` 也移进 archive

因为根目录还保留着后期较完整的脚本和项目。把 `.venv/` 一起移走，会让现在这些内容失去最直接的运行环境。

所以这次采用的是：

- 旧学习材料进 `archive/`
- 当前环境留在根目录
- 用文档把环境背景记录下来

## 归档与运行的关系

`generated/` 里的 `build/` 和 `dist/` 说明你当时已经开始尝试把脚本打包成可执行文件；它们是“运行痕迹”的一部分，所以被归档保留。

但如果今天想真正重新运行某个旧脚本，最好把它当成一次新的复习项目：

1. 先看脚本旁边有没有数据文件或 `.ui` 文件。
2. 再确认它依赖的是标准库、第三方库，还是当年机器上的某些本地环境。
3. 最后按需重建环境，而不是直接假定旧环境还能无缝复活。
